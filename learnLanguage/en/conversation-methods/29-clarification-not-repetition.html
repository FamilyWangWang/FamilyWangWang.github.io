29 对方没听懂意思时，把缺少的区别补出来

Sam 要把报名材料存进活动文件夹。两份文件都叫最终版，期限已经听清，再说一次“最终版”仍无法选择。本篇比较重复要求与补明内容，让澄清准确落到对象上。

阅读起点：适合单句大意能借中文读懂、却接不住下一轮回应的读者。跟住说话人和当前话题即可，不必先学完整套语气课。 不清楚一句话为何要接着上一轮理解时，先看前后文怎样改变意思（按需补读）。 连同讲解通读约6—10分钟，仅为篇幅估算；选读局部可更短。

先看回应在哪里错位

Sam: Please send the final version before lunch so I can put it in the event folder.
Lea: By final version, do you mean the form with my answers, or the copy with the organiser's notes as well?
Sam: The final version. I need it before lunch, because I won't be here this afternoon.
Lea: I heard the deadline. There are two files called final in the folder, and I don't know which one you want.
Sam: The one we talked about yesterday.
Lea: Yesterday we looked at both. Could you tell me whether you need the notes included?
Sam: Yes, I need the organiser's notes too.

这是重复要求、没有及时澄清对象的版本。Sam 请 Lea 午饭前发送最终版本，好存入活动文件夹。Lea 问指的是只有自己答案的表格，还是还含组织方批注的副本。Sam 再说最终版本，强调午饭前需要，因为下午不在。Lea 说期限听懂了，但有两份文件都叫最终，不知道要哪份。Sam 说要昨天谈过的那份。Lea 解释昨天两份都看过，再问是否要包含批注。Sam 这才说需要批注。

Lea 已把两个候选摆出来：只有答案，还是答案加批注。她听清了发送动作与午饭期限，缺的是识别文件的属性。再重复“最终版”或补下午不在，仍然没有回答这个区别。

“昨天谈过的那份”想调用共同背景，Lea 却补出昨天两份都看过，因此这个描述仍不唯一。共同经历不保证双方留下同一个记忆重点；与其争谁昨天有没有认真听，不如补上能区分对象的信息。

Lea 说期限已经听懂，是把已懂与未懂并列说明，帮助对方停止重讲时间。这个回应没有拒绝 Sam 的要求，而是在指出理解停在哪一层，Sam 才终于给出需要批注的答案。

换一种接法以后

Sam: Please send the final version before lunch so I can put it in the event folder.
Lea: Do you mean the copy with the organiser's notes, or just the form with my answers?
Sam: The copy with both your answers and the notes. I called it final because that's the version we agreed to keep yesterday. Sorry, the file names aren't very helpful.
Lea: Got it. I'll send that copy, not the answer-only file. Would you like me to rename it so the two are easier to tell apart?
Sam: Yes, please add with-notes to the name. I'll use that name when I ask for it again.
Lea: All right. I'll send it before lunch.

Sam 再请求午饭前发送最终版。Lea 问是带组织方批注的副本，还是只有自己答案的表格。Sam 明确要答案和批注都在的副本，说明自己叫它最终版，是因为昨天约定保留这一份，并为文件名不清楚道歉。Lea 确认会发送带批注的副本，不发只有答案的文件，问是否重命名方便区分。Sam 请在名称里加“with-notes”（带批注），以后也会用这个名称请求。Lea 同意午饭前发送。

Sam 先给“答案和批注都在”这个属性，再解释为什么叫最终版。接收者不用等到理由末尾才知道该选哪份；道歉也针对名称不清楚这一点，不把话题转成对自己能力的全面批评，再要求对方安慰。

Lea 的确认保留了有用的对比：发带批注的副本，不发只有答案的文件。前面确有两个候选，这样重述能排除错误发送；它不是规定每次收到消息都要逐字复述全部要求。

改名仍是进一步提议，Lea 先问，Sam 接受，并答应以后也用新名称请求。双方约定采用名称里的区分词，才可能减少下次歧义。对话没有展示文件已实际改名或发送；若一人换名、另一人仍用旧称，仍可能重新错位。

连起原文的表达线索

with both ... and ... 确定内容，answer-only 排除另一份。with-notes 是建议加进文件名的实际文字，表示带批注。

按理解困难的层次换说法

如果 Lea 不知道“批注”是什么，只说“要带批注的版本”仍不够，应说明是组织方写在表格旁的说明。区别词只有在双方理解它时，才能帮助识别对象；换成常用词或补含义，是另一层澄清。

换说法也要保留原要求。把带批注的副本说成“你填过的那个”，可能让两份文件都符合，唯一的区分属性便丢了。简洁应减少无效来回，不是删掉让动作正确的那一点。

若现实中还出现第三份草稿，旧的两项对比可能不足，需要补文件名、更新时间或共享位置。本例只有两份，第三份只是迁移条件。确认以后可以在发送时标明内容；收到的仍不符时，再核对实际选中和收到的文件。

分清没听清、不明白与不同意

声音没听清，可以放慢或重复；词义不明白，可以换词或解释；对象不确定，要补区分属性；对要求不同意，则需要讨论理由。把它们都归成“没听懂”，容易越说越响、越说越长，仍没碰到当前困难。

若对方只问“什么意思”，可以问是哪个词不明白，还是不知道下一步该做什么；已有候选时，也可先补最可能缺的区别，并允许对方纠正。目标是得到足够准确的信息继续，不是考到对方完整背出原句，也不必追究谁最初理解得慢。

澄清过后仍收到错误文件，不一定是理解失败。选对版本后点错附件，也可能发生。理解、选择和发送是相连的不同动作，应据实际证据找这一次的断点，别把它扩大成对认真程度或关系的全面判断。
