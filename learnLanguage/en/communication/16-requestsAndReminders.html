16 “方便的话”：请求、期限与提醒

“方便的话”听起来很客气，却不能替对方说明你什么时候需要结果。时间有弹性时可以留给对方安排；有真正期限时，则要把目标时间说出来，并询问能否做到。

下面五个场景分别解决不同问题，不是一段连续对话。

方便的话

希望对方帮忙，但确实允许对方安排时间。

你：

If you have a chance, could you send me the file?

如果有空，能把文件发给我吗？

对方可能回应：

Yes, I can send it this evening.

可以，我今晚能发。

你没有给出硬性期限，对方提出今晚发送。接下来如果今晚满足你的需要，可以接受；如果赶不上，就要把真正期限说明白。

你看什么时候方便

邀请对方提出可用时间。

你：

When would work for you?

你什么时候方便？

对方可能回应：

I’m free after three on Thursday.

我周四三点之后有空。

你让对方先提出可用范围。三点之后还不是具体见面时刻，需要继续约一个双方都能接受的时间。

麻烦帮我确认一下

你需要一个明确的核查结果。

你：

Could you check whether you received my message, please?

请您核查一下是否收到我的消息，好吗？

对方可能回应：

Yes, we’ve received your message.

是的，我们已经收到您的消息。

你请求核查的对象是消息是否收到。回复确认的是收到消息，并没有说消息中的事项已处理完。

check whether … 请求核查是否收到；对方用 we’ve received … 给出收到的结果。需要核对时，说清核对哪一项即可，不必把check和confirm理解成互不相容的两种动作。

我想提醒一下

约定的事情尚未发生，做中性提醒。

你：

Just a reminder about the file we discussed yesterday.

提醒一下我们昨天说过的那份文件。

对方可能回应：

Thanks for the reminder. I’ll send it today.

谢谢提醒。我今天会发。

提起昨天讨论的文件，把提醒落到一个共同知道的对象上。对方承诺今天发送，不能据此说文件此刻已经发出。

能不能尽量早点

你确实需要较早处理，提出可核对的目标。

你：

Would it be possible to send the file by noon tomorrow?

能最迟明天中午把文件发过来吗？

对方可能回应：

I can’t manage noon, but I can send it by five.

中午我赶不上，不过最迟五点可以发。

你提出最迟明天中午，对方明确赶不上，并给出最迟五点这个替代。中午没有成为双方约定；要接受新安排，还应把日期与上午、下午复述清楚。

情境1

Could you let me know by three p.m. tomorrow? Would that be possible?

请您最迟明天下午三点告诉我好吗？这样来得及吗？

这里的by表示最迟，包括那个时刻；不是严格要求在三点之前。第二个问题留给对方确认或提出别的时间。

情境2

Roughly what time would that be?

大约会是几点？

请求的是一个可安排的时间线索，不是要求对方重复“晚点”这两个字。

时间要求说清之后，有时还要纠正对方的理解，或把自己接受方案的条件补出来。
