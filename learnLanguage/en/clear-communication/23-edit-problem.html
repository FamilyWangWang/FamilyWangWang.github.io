23 改一封故障说明：把猜测与观察分开

你向同事说明系统导出文件的问题。这里所有系统、文件和操作均为虚构，目标是学习写清现象，不提供软件故障诊断。原稿先写尝试经过，又猜更新有问题，真正的现象很晚才出现。

原稿与它的意思

Perhaps the recent update has caused a server problem. I am not sure, but that was my first thought when it happened. I have tried two different lists and signed out and back in. Neither step changed the result. I have not checked another computer, so I do not know whether the problem is specific to this device. Other pages open as usual. I can send a screenshot of the loading symbol if it would help you investigate.

Could you check the export function when you have time today? I need the file for tomorrow's meeting, but I can use a copy of yesterday's list if necessary. Please let me know whether there is another way to export the current version. I am describing what I observed; I have not identified the cause.

I cannot export the attendance list from the project page. When I select “Download”, the page shows a loading symbol for about ten seconds and then returns to the list without creating a file. I tried this at nine this morning and again at ten, with the same result. The list itself still opens normally.

原稿的完整意思是：

也许最近更新造成服务器问题。我不确定，但事情发生时首先这样想。我试过两份不同的名单，也退出后重新登录，但结果没有改变。我还没有在其他电脑上测试，所以不知道问题是否只出现在这台设备上。其他页面都能正常使用。如果有帮助，我可以发送加载图标的截图，供你调查。

你今天有时间时，能否检查一下导出功能？我明天开会需要这个文件，必要时可以先用昨天名单的副本。请告诉我是否有其他办法导出当前版本。我目前是在描述观察到的情况，还没有确定问题原因。

我无法从项目页面导出参加者名单。选择下载后，页面会显示约十秒的加载图标，再回到名单，却没有生成文件。我今天九点和十点试过两次，结果都一样。名单本身仍能正常打开。

第一步：让读者先找到重点

先写能够观察的现象。原稿猜更新与服务器问题，把接收者带向一个没有证据的方向，后面却没有相应验证。成稿从当前不能完成的动作、点击后的过程和未生成文件开始，对方立即知道要检查哪项功能。时间与重试结果帮助定位，并不自动证明后台原因。

I cannot export the attendance list from the project page.

我无法从项目页面导出参加者名单。

第二步：安排支撑重点的信息

把已试步骤与未试范围放在第二段。两份名单和重新登录是已经做过的事，换电脑则尚未做。明确这点，比“我都试过了”更有用，也不会让同事错误排除设备差异。其他页面正常限定影响范围，截图是可提供的信息，而不是宣称文章附着一个实际文件。

I have tried two different lists and signed out and back in.

我试过两份不同的名单，也退出后重新登录，但结果没有改变。

第三步：保留可回应的下一步

最后说明任务需要和可接受的替代方案。今天检查是请求，明天会议解释为什么需要，昨天副本则是备用，不等于当前名单已可用。询问另一种导出方式打开可行路径；末句再说明只报告现象。编辑后，紧迫性没有消失，却不靠猜测原因或责备更新者增强。

Could you check the export function when you have time today?

你今天有时间时，能否检查一下导出功能？

哪些意思没有改变

删除猜测不是证明更新无关，而是不把未经检验的解释放在问题入口。后续若确有证据，可补入来源与检查结果。成稿也没有擅自声称错误已复现于所有电脑，或把两次尝试扩大为一直失败。保留观察边界有助于排查，而非显得表达不够专业。

I cannot export the attendance list from the project page. When I select “Download”, the page shows a loading symbol for about ten seconds and then returns to the list without creating a file. I tried this at nine this morning and again at ten, with the same result. The list itself still opens normally.

I have tried two different lists and signed out and back in. Neither step changed the result. I have not checked another computer, so I do not know whether the problem is specific to this device. Other pages open as usual. I can send a screenshot of the loading symbol if it would help you investigate.

Could you check the export function when you have time today? I need the file for tomorrow's meeting, but I can use a copy of yesterday's list if necessary. Please let me know whether there is another way to export the current version. I am describing what I observed; I have not identified the cause.

成稿的完整意思是：

我无法从项目页面导出参加者名单。选择下载后，页面会显示约十秒的加载图标，再回到名单，却没有生成文件。我今天九点和十点试过两次，结果都一样。名单本身仍能正常打开。

我试过两份不同的名单，也退出后重新登录，但结果没有改变。我还没有在其他电脑上测试，所以不知道问题是否只出现在这台设备上。其他页面都能正常使用。如果有帮助，我可以发送加载图标的截图，供你调查。

你今天有时间时，能否检查一下导出功能？我明天开会需要这个文件，必要时可以先用昨天名单的副本。请告诉我是否有其他办法导出当前版本。我目前是在描述观察到的情况，还没有确定问题原因。

回看修改

这里的编辑不是把日常说法换成技术术语，而是整理已知、未试与需要帮助的部分。每一项都回答调查者可能问的问题，原稿猜测则没有承担同样作用。通过这样的取舍，文字既可读，也保持证据范围。

还要区分描述过去和安排未来。两次尝试已经发生，同事检查尚未答应，备用名单也只是需要时可用。如果成稿为了短写成“导出坏了，今天处理”，就会丢掉关键现象、范围与对方回应空间。完整而清楚的说明，不一定比那句话短，却通常减少来回补问。

观察还可以按影响范围分层。页面打开正常、名单可以看、下载不生成文件，三者共同把困难缩到一个动作。如果只写“系统不能用”，会使同事先检查更大的范围；如果只写“没有文件”，又缺少触发过程。保留这些层次，篇幅增加一点却减少解释缺口。

若后续换电脑成功，应另发更新说明这项新证据，而不是静默改掉原先的未试状态。编辑是对当前材料的组织，不把未来可能获得的结果预先塞进成稿。这里的专业程度来自具体且可核对的报告，未必要使用更多听起来复杂的术语。
