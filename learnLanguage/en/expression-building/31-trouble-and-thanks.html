31 “麻烦你了”：先提出请求，还是为已经得到的帮助道谢

“麻烦你了”说在请求前，需要让 Maya 判断能否帮忙；说在核对后，则回应她已经做出的贡献。本篇沿一次活动介绍的日期核对，比较“麻烦你看一下”和“麻烦你了，还找到了旧通知”怎样进入两封完整消息。先看任务到了哪一步，再安排礼貌、范围与下一次回应；是否需要道歉，则另看有没有实际造成影响，不由“麻烦”这个词决定。

还没有答应时，把需要的帮助说出来

Hi Maya, could you check the two dates marked in the activity description? I need to send it tomorrow afternoon. You only need to compare those dates with the notice we received last week; I am checking the rest of the text myself.

If you have time, could you let me know by tomorrow at ten? If that is too short notice, please tell me and I will make another arrangement. Thanks for considering it.

I have put both files in the shared folder so you do not have to search through the old message thread. Nothing has been sent to the organiser yet.

Maya，你好。能否核对活动介绍里标出的两个日期？我明天下午要发出去。你只需与上周收到的通知比较，我自己检查其余文字。如果有时间，请最迟明天十点告诉我；若太仓促，请说明，我会另作安排。谢谢你考虑。两份文件都在共享文件夹，不必翻旧消息。目前还没向组织者发送。

第一封消息把“看一下”落到两个标出的日期：对照上周通知，其他文字由作者检查，两份材料已经放在共享文件夹。对方知道做多少、找什么依据，也少了翻旧消息的负担。中文里的体谅在这里成为具体安排，不需要逐字加一个“麻烦”。

材料已放好与核对已完成，是两件事。感谢对方考虑，只回应这项请求仍可被接受或拒绝；如果尚未答应，就先说“谢谢你明天帮我核对”，可能让对方以为分工已经决定。原消息留下时间太紧时说明的出口，作者才有机会另作安排。

明天十点是希望得到反馈的时点，明天下午是计划发送的时点。如果真正需要十点前完成核对，要把完成期限说清，不能让“告诉我一声”同时承担答复能否帮忙和提交结果两种未说明的要求。

帮助已经完成时，感谢落在具体贡献上

Thanks for checking the dates, Maya. Your note helped me see that the first notice had been replaced by a later one. I have now corrected the description and sent it to the organiser.

I also appreciate you finding the old notice, because I would otherwise have compared the dates with the wrong version. There is nothing else I need you to check today.

I will keep the newer notice beside the description so that the next person can see which information we used. If the organiser asks about the change, I can explain it using the files you found.

谢谢你核对日期。你的提醒让我发现第一份通知后来被新版取代。我已改好介绍并发给组织者，也感谢你找到了旧通知，否则我会拿错版本比较。今天没有其他需要你核对的内容。我会把新版通知与介绍放在一起，方便后来的人看依据；组织者若问修改原因，也能用你找到的文件说明。

第二封消息的阶段变了：核对已发生，Maya 的提醒又帮助作者发现旧通知被新版替代，随后改正介绍并发送。感谢因此有对象，也有可见作用；保留新版与相关文件，还能为后来的人解释依据。

“否则会拿错版本”是没有实际发生的另一种结果，不是报告已经拿错版本并发出。实际做过的是改好后发送。两层分开，才能看见帮助避免了什么，同时不把假设的错误当成事实。

今天没有更多需要核对的内容，给这次帮助一个收束。若只检查了一部分，感谢仍然成立，但只能感谢已完成的那部分；中文的客气不必逐字保留，完成范围却不能被一句感谢扩大。

对方回应以后，按实际完成范围继续

如果 Maya 只说“我先看看今天的安排”，可以感谢她查看日程，但日期核对仍未被接下。若她说“日期核对了，旧通知还没找到”，则感谢已检查的内容，资料来源仍待补齐。积极回应、接受任务与完成任务，需要沿实际答复逐步更新。

两项日期后来变成整份介绍，或今天的核对变成长期帮忙，都要重新说明增加了什么，并等待接受。更多客气词不能替代新的分工；过去提供过帮助，也不意味着今后相同请求自动成立。

这里最有用的判断是：当前需要对方接受一项帮助，还是知道帮助产生了怎样的贡献？范围、材料、答复余地和结束后的结果通知都围绕这一判断组织，便能让消息完整而少些猜测。

本篇表达怎样发挥作用

could you 引出请求；Thanks for considering it 感谢考虑，Thanks for checking 感谢已完成的核对。would otherwise have compared 描述未发生的另一种可能，have now corrected 才报告当前结果。不要把两种完成形式都读成实际做过。

Thanks for 后面用 considering／checking 的 -ing 形式，分别感谢考虑或核对。had been replaced 把通知被替代放在发现以前；would otherwise have compared 则是假设中本会作出的比较，两者不能都当作实际错误。
