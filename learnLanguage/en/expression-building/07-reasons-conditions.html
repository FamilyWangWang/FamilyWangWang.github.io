07 加上原因和条件，但别改变承诺的范围

“因为”和“如果”都能把句子连接起来，但它们承担的任务不同。原因解释为什么会这样，条件说明在什么情况下才会这样。把二者混在一起，可能把尚未确定的事情说成已知事实，或者把有前提的安排说成无条件承诺。

你正在整理草稿，其中需要的数据还没收到。你想告诉同事：今天收到数据的话，明天就能发出草稿。

I can send the draft tomorrow if I get the figures today.

如果我今天收到数据，明天就可以发出草稿。

if I get the figures today 是条件。它限制的是明天能够发送这件事，不能读成“我已经会在今天收到数据”。can 则说明条件满足后能够完成，并未单凭这一句就宣布发送已经确定。

前提不能在改写中消失

如果你已经准备好在收到数据后发送，并且愿意作出这一安排，可以把能力说明改成有条件的承诺。条件仍要保留。

I’ll send the draft tomorrow if I get the figures today.

如果我今天收到数据，我明天会发出草稿。

在这个安排情境里，I’ll send 比 I can send 更明确地承担行动，但 if 后的前提依然有效。常见的未来条件句用 if I get，不需要因为谈的是未来就在条件部分写 will get。这里只讨论普通的条件用法，will 在表示意愿等其他意义时另有用法。

“明天发给你”更短，却删掉了数据这个前提。自然改写首先要保住事实与责任，不能只比较哪个版本字数少。

原因需要一个已经成立的背景

如果数据昨天已经收齐，你是在解释为什么明天就能发出草稿，便可以说原因。

I can send the draft tomorrow because I already have all the figures.

我明天可以发出草稿，因为所有数据我已经拿到了。

because 后面的内容被说话人作为已经成立的理由提出。它与前面的 if 版本不同：那个版本等待条件是否满足，这个版本说明条件已经具备。句子依然用 can，说明能够发送；如果还没决定实际发送，就不要自行改成承诺。

不确定时，把未知部分明说

如果你连数据什么时候到都不知道，与其给出一个没有根据的日期，不如说明自己会确认什么。

I’m still waiting for the figures. I’ll confirm the delivery date once I have them.

我还在等数据。收到后，我会确认交付日期。

这里承诺的是确认日期，并没有承诺明天交付。them 指前一句的 figures，让两个句子连续起来。把未知信息明说出来，通常比用一个听起来很积极、实际上没有依据的时间更有帮助。

原因与条件看似只多了一个连接词，实际却影响听者怎样理解整个安排。下一篇将把注意力转到另一类补充：怎样让对方认出你说的是哪一个东西。
